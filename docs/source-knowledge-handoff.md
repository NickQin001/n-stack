# 来源核实与领域知识交接

Nick 已确认按此交接：他把平台上的一条视频交给主管，再由主管分站协调。各站遵守 [N0 证据纪律](../principles.md) 与 [共享前置原则](../principles/shared-preamble.md)。

流水线尚未自动化。主管接收材料、安排下一站、汇报结果和阻塞。下表的 bot 名是当前实例，换执行者时保持同一职责。实例名记在本页；`agents/` 仍只有原有的未实现角色桩，本仓库没有这些实例的提示词或调度。

## 职责

| 职责 | 做什么 | 当前实例 |
| --- | --- | --- |
| 主管 | 接收 Nick 交来的材料，协调下一站，汇报进展、缺口和阻塞 | 主管 |
| 平台管理员 | 访问对应平台；实际获取来源，读取并核实实际内容 | B站管理员 |
| 知识整理 | 保留原始字幕；写整洁版、完整总结、带时间戳的事件和处理步骤；标出不清楚之处 | 视频知识整理bot |
| 领域助手 | 核验官方规则的适用地区和日期；视频经验与法规分开；可追溯入库；之后按已入库内容逐步问答 | 交通事故处理员 |

顺序：

1. Nick 把视频交给主管。
2. 平台管理员先实际获取、读取并核实。这一站未完成时，后面的站不开始。
3. 知识整理只处理管理员本轮核实过的材料。已有成果可以复用，仍须等这次核实之后再采用。
4. 领域助手核验并写入知识库。以后 Nick 问到该领域时，按已入库内容逐步说明：做什么、保留哪些证据、报警之后如何如实沟通。

## 每站交接清单

交给下一站时带上这些字段。没有的项写「未提供」或「待确认」。

| 字段 | 要求 |
| --- | --- |
| 来源 URL | 用户给出的链接。未实际打开过的地址保持原样 |
| 标题 | 用户给出的标题，或本轮实际读到的标题。两处都有则都记下，并写明哪一处是实测 |
| 作者 | 本轮实际查到才填写 |
| BV | 本轮实际查到才填写 |
| 材料路径 | 相对路径或通用路径 |
| 已读取范围 | 本轮实际读过的部分。没读写「未读取」 |
| 获取方式 | 哪一站、用什么方式拿到。没拿到写「未获取」 |
| 缺口 | 还缺的材料、字段或核验 |
| 状态 | `未开始` / `获取中` / `待确认` / `已观察` / `已入库` / `阻塞` |

状态用法：

- `未开始`：主管尚未把这一站派出去。
- `获取中`：素材还在获取，尚无正文。
- `待确认`：已有材料或说法，本轮还没核对。
- `已观察`：本轮实际读过，并写了已读取范围。
- `已入库`：交付物已经写入知识库，且能回到来源、路径和已读取范围。只有这个状态可以称为这一条完成。
- `阻塞`：获取、读取或核验失败，写明卡在哪一站。到此停止，不补剧情。

无内容，或清单里只有空模板，不能标完成，也不能标 `已入库`。证据用词仍按 N0：没读到的内容保持「待确认」或「仅声称」。

## 交付物

知识整理在平台管理员已经实际获取并读取之后交出：

- 原始字幕保留
- 整洁版
- 完整总结
- 带时间戳的事件和处理步骤
- 不清楚之处单独标出

领域助手交出：

- 官方规则写明适用地区和日期；未核验的保持「待确认」
- 视频经验和法规分栏。视频情节单独成栏，不写成法条
- 入库记录能回到来源 URL、材料路径和已读取范围
- 后续问答只引用已入库、且状态允许引用的内容，按步骤说明

与交警或其他执法人员沟通时，只使用已核对的事实。沟通模板不包含诱导对方定责的说法。

## 适用边界

- 紧急现场先保证人员安全，并按现场需要求助。知识库查询和站间交接不推迟报警、离险或救护。
- 对外报警、联系外部人员或代为提交，需另有明确授权。
- 本流程不授权读取用户本机文件。访问用户登记过的电脑上的文件、上传或外传，每次另行取得明确允许。
- 公开文档使用相对路径或通用路径。内部实例的绝对路径、bot 的内部标识，以及个人健康等私密数据，不写入公开文档。
